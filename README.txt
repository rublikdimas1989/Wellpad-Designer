ПРОЕКТИРОВЩИК КУСТОВОЙ ПЛОЩАДКИ v93c
====================================


Запуск Windows: дважды нажмите START_APP.bat.
Требуется Python 3.10+ со стандартной библиотекой Tkinter.
В архиве нет старых выпусков, тестовых файлов и изображений.
Свои проекты храните в папке «Проекты» и сохраняйте её перед обновлением.

НОВАЯ СХЕМА РАБОТЫ (база исходников v84)
---------------------------------------
1. «Создать проект»: только исходная геометрия и базовый хребет.
2. «Рассчитать»: собственные маршруты внеосевых скважин и точки врезки
   ищутся по конечному ортогональному графу. Шаг обычной сетки — 1 м;
   в граф добавляются точные координаты портов и касательные к зонам.
   Стоимость полного варианта включает трубы, отводы, тройники,
   необходимые фиксированные плиты и плиты-заполнители. Осевые скважины
   и пожарный узел сохраняют прежние особые правила подключения.
   Плиты отображаются сразу вместе с рассчитанными линиями.
3. «Оптимизировать»: дополнительно рассматриваются совместные замены
   двух-трёх маршрутов, новые физические тройники одной среды и общие
   опорные коридоры разных сред. Для каждого кандидата заново проверяются
   геометрия, обязательная связность до центральной магистрали,
   защита скважин, коридоры, опоры и вся смета. Более дорогая
   конфигурация не принимается. Пожарная линия никогда не входит в пучки.

ПРОЦЕСС ПОИСКА НА ЧЕРТЕЖЕ
------------------------
Включённый по умолчанию флажок «Показывать поиск линий на чертеже»
отображает проверяемые линии оранжевым, текущий узел графа и временно
полученный вариант сети; строка состояния сообщает число проверок,
источник маршрута и лучшую стоимость. Фоновый поток не блокирует интерфейс.

ОГРАНИЧЕНИЯ
-----------
Поиск конечен: обычный шаг сетки 1 м; не больше 4400 расширенных
узлов для каждой дополнительной A* попытки. Оптимизация ограничена
числом полноценно проверенных конструктивных конфигураций и временем.
Гарантии абсолютной глобальной оптимальности в непрерывном пространстве НЕТ.
Невозможные/прерванные поиски должны отображаться как ограничения, а
не как доказательство оптимальности. Параметры стоимости можно менять.

Базовые цены: труба 2 000 ₽/м; отвод 4 500 ₽; тройник 6 000 ₽;
плита 1,2 × 3 м — 12 000 ₽. Для плит других типоразмеров цены не заданы.

ПОЛИТИКА ПОСТАВКИ
----------------
Внутри ZIP только необходимые исходные модули, START_APP.bat и README.txt.
История версий и тестовые отчёты остаются вне релизного архива.

ВЕРСИЯ 87: стандартная точка врезки нового проекта X=200, Y=90.
На этапе «Оптимизировать» проверяются два/три разных трубопровода
на опорах 1,2 × 3 м. Изоляция сред и межосевое расстояние транзита 0,30 м обязательны.
Проверка допустимости (зазоры) приоритетнее экономии: сначала допустимая геометрия, затем цена.
Поиск ограничен числом кандидатных комбинаций, глобальный минимум не доказан.

ВЕРСИЯ 89: ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА СВЯЗНОСТИ
----------------------------------------
При «Рассчитать» и при каждом испытании в «Оптимизировать» выполняется
проверка физического графа трубопроводов по каждой среде.
Скважины, точка врезки и пожарный узел ДОЛЖНЫ иметь непрерывный путь до
трубы своей среды на центральной плите; две соединённые между собой, но
отрезанные от магистрали скважины — НЕ допустимая проектная сеть.
Физический тройник должен действительно касаться линии; просто соседние
трубы и перекрёстные пересечения разных сред НЕ объединяются.
Проверяется КАЖДЫЙ обязательный порт, и при обрыве отклоняется вся сеть
без расчёта итоговой стоимости. Во время промежуточного выбора положения
центральной плиты допустимо ещё не иметь пожарной линии; окончательная
сеть ОБЯЗАТЕЛЬНО проверяется уже с пожарным узлом.

В «Детали» → «Фактические подключения» показываются: обязательные линии,
действительно выбранные точки, реальные координаты трасс, длины, отводы,
подтверждение пути к центральной плите и фактические счётчики поиска,
причины отказов (если они были сохранены). Отчёт не содержит выдуманных
непроверенных вариантов или доказательства глобального оптимума.

Стандартная зона скважины: радиус 5 м (v88).
Для внешних транзитов межосевое расстояние: 0,30 м (v88).
Стандартная точка врезки: X=200, Y=90 (v87).

ВЕРСИЯ 89 (correct): ПУЧОК 0,30 м И ТРОЙНИКИ
-------------------------------------------
По итогам разбора истории разработки (GPT) исправлены корневые ошибки:

1) Отбор общего коридора больше не смешивает хребтовый lane_gap с
   транзитным межосевым 0,30 м: пакет DN159 на плите 1,2 м снова виден
   оптимизатору (_corridor_overlap / transit_corridor_overlap).
2) Кандидат «общего коридора» сажает оси на 0,30 м (не «радиусы+0,30»).
3) Представительный прогон — по длине; overlap ≥ 2 м; донор от 5 м;
   приоритет «второго ряда» плит (кейс скв. 9 / pressure).
4) Тройники одной среды ранжируются по экономии длины; join→join без
   якоря на магистраль не предлагается; повторный проход пучков после
   тройников. Связность до центральной плиты (v89) сохранена.
5) JSON-проекты без смены схемы. В архиве только рабочие модули.

Дополнение (скв. 10): посадка к краю уже собранного пакета 0,30 м без
U-turn через старый gate; синтез сдвига оси, если в каталоге нет порта.

Дополнение (принуд. пучок): почти параллельные коридоры (2–3 среды,
в т.ч. скв. 9/10 + продуктовая) принудительно стягиваются в пакет
межосевых 0,30 м на плите 1,2 м; отбор учитывает число плит 1,2×3 м
раньше цены трубы, чтобы второй ряд опор не «побеждал» из-за чуть
более короткой одиночной трассы.


ВЕРСИЯ 90: ПУЛ ПУТЕЙ И КОМБИНАЦИИ
---------------------------------
«Рассчитать»: для каждого элемента/среды сохраняется до 100 самых дешёвых
НЕЗАВИСИМЫХ путей (труба+отводы). Пучки и тройники на этом этапе
игнорируются. Сразу после расчёта пишется JSON в папку «Снимки_расчёта»
(настройки, скважины, пул путей).

«Оптимизировать»: перебирает комбинации путей из этого пула (одиночные,
пары, тройки + принудительные пучки/тройники). Общая плита 1,2×3 м
оплачивается один раз; совпадающий участок одной среды — один раз
(физическая сеть через make_network). Полный перебор всех 100^N не
гарантируется: поиск ограничен бюджетом проверок и временем.


ВЕРСИЯ 91: ОСЕВОЕ ЯДРО (ЧИСТКА)
-------------------------------
Удалены/отключены подключения внеосевых скважин и точки врезки.
«Рассчитать» строит только:
  • элементы (координаты скважин/пожарного/врезки как метки);
  • хребет осевых скважин;
  • осевые отпайки и плиты на оси;
  • центральную плиту;
  • пожарный узел и его плиты;
  • показатели стоимости.

«Оптимизировать» временно ничего не меняет — внешний алгоритм будет
переработан с нуля. Снимок JSON после «Рассчитать» — в «Снимки_расчёта».


ВЕРСИЯ 92: ВНЕШНИЕ ПОДКЛЮЧЕНИЯ (НЕЗАВИСИМО + ОПТИМИЗАЦИЯ)
---------------------------------------------------------
Точки подключения внешнего элемента:
  • бок хребта только на хребтовых плитах, с внешней стороны (не со стороны НДС);
  • или дальний торец хребта (противоположный ЦП);
  • бок центральной плиты только со стороны элемента (торцы ЦП запрещены).

«Рассчитать»: для каждого внешнего слота (внеось/среда, врезка) перебирает
точки и ортогональные пути маленькими шагами, отсекает нерациональные,
запоминает до 40 самых дешёвых, показывает лучшие независимые линии.
Плиты 1,2×3 временно равномерно, зазор 3 м (до 6 м). Линии не видят друг друга.

«Оптимизировать»: комбинации запомненных путей. Одна среда → общая труба
(стоимость участка один раз). Разные среды на общих плитах → плита один раз.

ВЕРСИЯ 93: ТРАНЗИТНАЯ МАГИСТРАЛЬ (optimize_algorithm.py)
-------------------------------------------------------
Либо независимая линия, либо пучок 0,30 м на общих плитах 1,2×3.
Синтез магистрали: скважина 10 + врезка на одной вертикали (не перебор
готового пула). Общая сетка плит на перекрытии. Совпадение разных сред

ВЕРСИЯ 93b: СЛИЯНИЕ БЛИЗКИХ РЯДОВ ПЛИТ (nudge)
----------------------------------------------
Если две вертикали идут почти рядом (разнос ≤3 м) с отдельными рядами
плит 1,2×3 — при «Оптимизировать» стягиваются до пучка 0,30 м и плиты
оплачиваются один раз (цель: дешевле).
