# Условия текущей программы Wellpad Designer (v91)

Документ фиксирует **фактически действующие** правила после чистки осевого ядра (v91), плюс условия, которые ещё числятся в справке/коде, но **не работают** для внешних трасс.

Оценки в скобках:

| Метка | Смысл |
|---|---|
| **НУЖНО** | Сохранять при новой проработке |
| **УТОЧНИТЬ** | Нужно, но формулировка/число спорны |
| **УСТАРЕЛО** | В справке/коде есть, но внешний алгоритм отключён |
| **КОНФЛИКТ** | Противоречит другому правилу или текущему режиму |
| **МЕРТВО** | Параметр/правило не влияет на расчёт |
| **ОГРАНИЧЕНИЕ** | Технический предел, не норма проектирования |

---

## 0. Что программа реально делает сейчас (v91)

1. Размещает элементы: скважины (ось / вне оси), пожарный узел, точку врезки (как координату).
2. Строит **только осевое ядро**:
   - хребет по осевым скважинам;
   - осевые отпайки к своей нитке хребта;
   - центральную плиту;
   - пожарный узел + его плиты;
   - плиты на оси / опоры ядра;
   - смету (труба / отводы / тройники / плиты 1,2×3).
3. После «Рассчитать» пишет JSON в `Снимки_расчёта/`.
4. «Оптимизировать» — **заглушка** (ничего не меняет).
5. **Не строит** трассы внеосевых скважин и точки врезки.

**Комментарий:** это правильная «точка обнуления». Дальше внешний алгоритм лучше писать поверх чистого ядра, а не поверх старых слоёв.

## 1. Рабочий процесс

| № | Условие | Статус | Комментарий |
|---|---|---|---|
| 1.1 | Элементы → «Рассчитать» → (опц.) «Оптимизировать» | **НУЖНО** | Последовательность ок; Optimize пока пустой |
| 1.2 | «Рассчитать» = осевое ядро + снимок JSON | **НУЖНО** | Главный рабочий режим v91 |
| 1.3 | «Оптимизировать» ищет пучки/тройники/внешние комбинации | **УСТАРЕЛО** | Код отключён; в README v87–v90 ещё описано — **КОНФЛИКТ со справкой** |

| 1.5 | Показ поиска на чертеже (оранжевый overlay) | **УТОЧНИТЬ** | Для ядра почти не нужен; пригодится снова на внешних трассах |
| 1.6 | Снимок настроек + скважин в `Снимки_расчёта/` | **НУЖНО** | Оставить для разбора ошибок |

## 15. Главные конфликты и «наслоения» (итог ревизии)

1. **Справка vs код (v91):** длинные §3/§5/§10/§19 про внеось/врезку/пучки описаны как живые, а генерация связей отключена.  
   → Нужна короткая «актуальная» справка и архив «исторических» правил отдельно.

2. **Два зазора:** хребет 0,25 м vs транзит 0,30 м. Само по себе верно, но старый код часто их смешивал.  
   → При возврате внешних трасс держать **два именованных параметра**, не один `lane_gap`.

3. **Смета плит:** в J только 1,2×3, хотя осевые/центральные плиты обязательны конструктивно.  
   → Либо ввести цены, либо явно писать «не тарифицируются».

4. **Мёртвые коэффициенты** (`bend_penalty`, `crossing_penalty`, `corridor_weight`, `corridor_saving_per_m`, `shared_corridors`) живут в UI/JSON.  
   → Прячут смысл модели; лучше убрать из основного экрана или пометить «не используется».

5. **Голосование стороны хребта по внеоси/врезке** при том, что они не подключены.  
   → Для ядра логичнее не учитывать «молчунов» или учитывать только как геометрические якоря по явному флагу.

6. **Пожарные правила про транзит/пучки** частично ссылаются на объекты, которых сейчас нет.  
   → Правила сохранить, но пометить «для будущего внешнего слоя».

7. **Старый `routing.build` огромный** и всё ещё содержит внешнюю логику; публичный вход уже уходит в `axis_core`, но мёртвый код создаёт ложное ощущение, что правила ещё живы.  
   → Дальнейшая чистка: вынести/удалить неиспользуемые ветки `optimize_tie_corridor`, `route_well_via_tie`, `optimize_groups` и т.п.

## 16. Что оставлять как ядро будущей модели

**Оставить без споров**
- Ось НДС, осевые скважины, хребет, ЦП 6×1,75, пожарный торец-only, охранные 5 м, запрет четверников, запрет ложных межсредовых тройников, раздельные зазоры хребет/транзит, смета труба+отвод+тройник (+ явно решить плиты).
